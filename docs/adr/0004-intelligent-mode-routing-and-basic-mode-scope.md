# 智能模式路由与基础模式职责

系统需要同时支持复杂图纸重建和平面轮廓直接拉伸。旧设计中，基础模式既负责执行平面拉伸，又尝试通过本地规则判断是否为多视图工程图；这让一个本应只做执行的路径承担了不完整的图纸裁决职责，也会把本地误判直接放大成用户可见的阻断。

## Considered Options

**A. 继续让基础模式自行判断图纸类型，并在怀疑多视图时阻断。**

实现改动最少，但会让基础模式长期保留半套智能判断职责；本地规则误判时，用户即使明确选择平面拉伸，也仍会被错误阻断。

**B. 让智能模式负责所有图纸类型判断；基础模式只作为已知平面图的拉伸执行路径。**

职责最清晰：智能模式负责识别、裁决和路由；基础模式负责轮廓建模和拉伸。选中。

## Decision

1. 智能模式是负责识别图纸类型、选择建模路径并处理复杂图纸的主入口。
2. 基础模式是已知输入可按平面图处理时使用的通用拉伸执行路径；它默认输入就是可平面拉伸图，不再负责视图类型裁决。
3. 智能模式若判断图纸为“可平面拉伸图”，可转交基础模式执行拉伸。
4. 智能模式是否转交基础模式，应依据其最终语义判断；本地规则只提供视图初判和证据，不单独触发路由。
5. 智能模式完成裁决后，基础模式不再进行二次视图审核，只负责执行。
6. 用户手动选择基础模式，等价于明确声明按平面拉伸处理；系统不再在基础模式中尝试纠正其图纸类型选择。
7. 旧的“基础模式检测到二视图/三视图后阻止直接拉伸”规则废弃。
8. GUI 应在模式选择处说明：基础模式仅负责平面拉伸，多视图或复杂图纸请使用智能模式；执行时不再追加阻断式确认。
9. 若用户发起智能模式任务，而系统内部转交基础模式执行，外部结果仍记为“智能模式完成”，并记录其建模路径为基础拉伸。
10. “单视图”只是视图分类，不等同于“可平面拉伸图”；智能模式只有在确认基础拉伸足以表达图纸时，才选择该路径。
11. 视图类型和建模路径必须分开表达：前者描述图纸如何表达零件，后者描述系统应如何建模。
12. LLM 负责输出结构化语义判断；程序依据这些语义按固定规则选择最终建模路径。
13. 处理结果应显式记录 `mode` 与 `modeling_path`：前者表示用户选择的入口，后者表示系统最终采用的建模方式。
14. `modeling_path` 当前只保留 `planar_extrude` 与 `semantic_reconstruction` 两个取值；待系统真正具备新执行链后再扩展。

## Consequences

- 基础模式将从“弱判断 + 执行”收敛为纯执行器，职责更稳定。
- 视图裁决集中回智能模式，便于继续强化大语言模型语义校正。
- GUI 需要把旧的硬阻断提示替换为模式说明。
- 日志和结果对象需要能够表达“外部模式”和“内部建模路径”的区别。
