# 智能处理编排与分析命名

随着智能模式逐步承担视图语义校正、语义裁决、建模路径选择和执行分发，原有“智能分析”概念已经不足以描述整条主流程。系统需要区分分析子过程、语义重建内核和更外层的处理编排，否则 `Analyzer` 命名会继续遮蔽真实职责。

## Considered Options

**A. 继续把整条智能流程都称为“智能分析”。**

改动最少，但会把分析产物、路径裁决和处理结果继续混在一起，读者难以判断谁负责理解、谁负责执行分发。

**B. 立即把 `IntelligentEngineeringAnalyzer` 重命名为新的编排器类。**

名实最一致，但会立刻引入 import、文档、缓存和兼容迁移成本；当前收益主要是命名收益，尚不足以覆盖迁移噪音。

**C. 先在领域模型中建立“智能处理编排”，保留现有类名作为阶段性兼容。**

先把职责说清楚，再决定何时迁移实现命名。选中。

## Decision

1. “智能处理编排”是智能模式中的主流程组织层；其核心职责是把“智能分析结果”转化为“智能处理结果”。
2. “智能分析”保留为智能处理编排内部的分析子过程，而不是整条智能模式主流程的总称。
3. “语义重建内核”是智能处理编排内部调用的深层模块，负责语义裁决、零件语义生成、建模路径选择以及建模指令或平面拉伸路由产出。
4. 智能处理编排只消费语义重建内核返回的路径裁决，不重新持有 `planar_extrude` 与 `semantic_reconstruction` 的判定规则。
5. “智能分析结果”包含视图、尺寸、本地关系、语义结果和 `modeling_path_decision` 等理解性产物；“智能处理结果”包含最终 `modeling_path`、执行分支、产物和任务状态。
6. 分析缓存只缓存智能分析结果，不缓存用户操作、任务状态或最终产物。
7. `modeling_path_decision` 属于智能分析结果；实际执行后的 `modeling_path` 属于智能处理结果。
8. `IntelligentEngineeringAnalyzer` 当前保留类名以降低迁移噪音，但它的职责应被文档化为“智能处理编排”；后续如需重命名，应作为单独迁移处理。

## Consequences

- 代码和文档需要区分“分析”“编排”“内核”三层职责。
- `IntelligentEngineeringAnalyzer` 的当前名字将形成一笔有意识的命名债务，而不是继续被误解为职责完整表达。
- 缓存、报告和任务结果可以围绕“理解性产物”与“执行性结果”形成更清楚的边界。
