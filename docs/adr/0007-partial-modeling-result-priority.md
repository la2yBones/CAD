# 部分建模成果优先策略

智能处理的目标需要从“只有完整建模才算成功”扩展为“优先生成可检查、可导出的主体模型”。在工程图纸信息不完整、细节语义不确定或 FreeCAD 局部特征执行失败时，系统应尽量保留已经可靠生成的主体成果，而不是让孔、倒角、圆角、槽、螺纹或局部切除等细节失败拖垮整次建模。

这个决策不能简单并入 `completed`，因为部分成果并不等同于完整模型；也不能继续归入 `failed`，因为用户已经获得了可打开、可检查、可继续人工修正的模型主体。

## Considered Options

**A. 继续保持严格完成语义。**

任何关键字段不完整、细节建模失败或脚本局部异常都使任务进入 `failed` 或 `needs_clarification`。这能降低误导风险，但会让许多已经生成主体模型的任务被视为失败，用户无法优先获得可检查成果。

**B. 将缺少细节的模型也标记为 `completed`。**

用户能看到成功结果，但状态语义被稀释。GUI、CLI 和批处理统计无法区分完整模型与只完成主体的模型，后续质量评估也难以追踪跳过的细节。

**C. 新增 `partial_completed`，把可导出的主体模型建模为部分完成。**

主体外形、主要体量、方向和关键尺寸来源可靠且模型可导出时，任务返回 `partial_completed`；细节语义不足、低置信或局部执行失败时记录为跳过细节。选中。

## Decision

1. 新增管线状态 `partial_completed`，表示系统生成了部分建模成果。
2. 部分建模成果必须满足：主体模型可打开、可检查、可导出；主外形、主要体量、方向和关键尺寸来源没有明显错误。
3. 孔、倒角、圆角、槽、螺纹、局部切除等不会改变主体外形和主要体量的细节，可以因语义不足、低置信特征或 FreeCAD 局部失败被跳过。
4. 跳过细节必须结构化记录，至少表达被跳过的特征、原因和风险；不能只混入普通 warning 文本。
5. 当不确定的是主体外形、主要体量、方向或关键尺寸来源时，系统仍应进入 `needs_clarification`，而不是生成部分建模成果。
6. 不允许为了获得部分成果而生成与输入图纸无关、主体比例明显错误或方向明显错误的模型。
7. 建模指令和 AI 脚本执行应支持局部容错：主体建模优先完成并保存，细节特征逐项尝试，失败时记录为跳过细节。
8. `partial_completed` 不等同于 `failed`，也不等同于 `completed`；GUI、CLI、批处理统计和报告应单独呈现。
9. 实现顺序应先扩展结果状态、跳过细节记录和执行器识别逻辑，再调整建模提示词；否则提示词输出的部分成果信息会被下游丢失或误判为普通 warning。
10. 为兼容旧调用方，`partial_completed.success` 为 `True`；新代码必须通过 `status == partial_completed` 区分完整完成和部分完成。

## Consequences

- 用户可以优先获得可检查的主体模型，即使部分细节尚未建成。
- 执行器和建模脚本需要区分主体失败与细节失败。
- 结果对象需要承载跳过细节的结构化信息。
- GUI 和 CLI 需要显示部分完成状态、缺失细节和风险说明。
- 旧批处理统计中部分建模成果会计入成功；需要更细统计时应读取 `status`。
- 测试需要覆盖“主体导出成功但细节失败”的路径，确保该路径返回 `partial_completed` 而不是 `failed`。
- 语义裁决仍然保护主体级不确定性；部分成果策略不能绕过关键尺寸来源、主体方向和主外形的安全判断。
- 建模提示词需要补充主体优先、细节局部容错和结构化跳过细节要求，但应在下游结果协议具备承载能力之后再落地。
