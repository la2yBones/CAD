# 保底追问与补充建模提示

追问机制原本以结构化字段补全为主，系统在语义不足时向用户列出问题，用户必须逐项回答后才能继续。实践中，这类问题常常难以和图纸上的具体位置对应，也不容易让用户表达“这个零件大概应该怎么建”。因此追问不应成为常规建模步骤，而应作为系统无法在安全边界内继续自动处理时的保底措施。

## Considered Options

**A. 继续使用强制字段补全。**

实现简单，结构化程度高，但用户很难回答图纸上下文不足的问题；无法表达自然语言建模意图，容易让流程卡在并不重要的细节上。

**B. 改成纯自然语言补充。**

用户表达更自由，但结构化答案、路径契约恢复和确定性测试都会变弱。系统也难以判断哪些主体级字段已经被可靠补足。

**C. 保留结构化追问，同时允许可选补充建模提示。**

系统仍展示具体问题，但用户可以额外填写自然语言说明；当具体问题难以回答时，补充提示可单独提交，作为局部恢复的额外上下文。选中。

## Decision

1. 追问机制是保底措施，不是常规建模步骤。
2. 只有主体外形、主要体量、方向、关键尺寸来源或建模路径执行合同无法可靠裁决时，追问才应阻塞处理。
3. 追问界面应展示结构化问题，同时提供可选的补充建模提示输入。
4. 用户可以只填写补充建模提示；非必填结构化问题不得强制全部回答。
5. 补充建模提示参与局部恢复，不重跑 CAD 解析、视图识别或尺寸提取。
6. 补充建模提示可以修正建模意图和细节解释，但不能直接覆盖已解析出的图纸事实、关键尺寸来源、主体方向或主体外形。
7. 当用户补充提示与大模型语义冲突时，用户语义覆盖必须记录覆盖项、原因和风险；主体级冲突仍应继续澄清或失败。
8. 如果补充提示足以让系统在安全边界内继续，未结构化回答的细节追问不应继续阻塞流程；相关不确定细节应进入跳过细节或部分建模成果路径。
9. 用户澄清统一规范化为 `ClarificationResponse`，其中结构化答案、`user_modeling_hint`、来源阶段和冲突策略分开保存；旧字典输入继续兼容。
10. 默认冲突策略为 `drawing_facts_override_user_hint`：补充提示可以解释建模意图和细节优先级，但不能覆盖图纸事实、关键尺寸来源、主体方向或主体外形。
11. 零件语义生成和建模指令生成提示词都必须显式列出补充提示及其冲突策略，要求模型以图纸事实和 `semantic_policy.dimension_plan` 为准；建模指令阶段应将可跳过细节写入 `skipped_features`。
12. 系统不在本地用正则或关键词判断补充提示是否冲突；补充提示应透传给建模大模型，并由提示词中的冲突策略约束模型解释和取舍。
13. 结构化追问问题统一通过 `clarification_question()` 构造，保持 `text`、`reason`、`example`、`options` 等字段格式一致。
14. 路径层追问若仍缺少专用路径契约字段，但用户已经提供自然语言补充提示，则不应反复追问同一问题；系统应改交由语义重建路径结合补充提示继续尝试。

15. 路径层降级到语义重建时，必须把原专用路径、缺失契约字段和追问问题作为 `path_clarification_fallback` 写入零件语义，传给建模指令大模型。
16. 语义追问恢复和路径层追问恢复在进入建模前必须复用同一组局部恢复 helper，集中处理语义置信度、路径契约阻塞、补充提示降级和恢复结果组装。
## Consequences

- 路径层降级上下文会进入建模提示，使大模型知道哪些专用路径字段缺失，并优先尝试生成可完成的主体或部分成果。
- 局部恢复分支的建模决策保持在语义重建管线内部的单一位置，后续新增追问来源时不应复制 blocked/fallback/execute 分支。

- GUI 追问从强制问卷变为补充信息面板。
- 局部恢复需要把 `ClarificationResponse` 透传给语义裁决、零件语义生成和建模指令生成；仅在兼容旧接口时退回普通 answers 字典。
- 测试需要覆盖只填写补充建模提示的路径。
- 语义生成和建模提示词测试都需要覆盖冲突策略是否被提升为显式规则，避免后续 prompt 改动让补充提示重新变成普通上下文字段。
- 本地只负责规范化和透传补充提示，不对自然语言提示做阻塞式冲突判断；冲突处理交给具备图纸上下文的大模型，同时保留“图纸事实优先”的提示词约束。
- 追问问题本身仍需要继续改进可读性和图纸定位能力，但不能把所有细节不确定都升级成阻塞追问。
- 新增追问来源时应复用统一 helper，避免内部字段名或缺少示例的文案再次进入 GUI。
- 专用路径契约问题不应因为用户选择自然语言补充而形成循环；必要时应降级为语义重建路径继续尝试生成部分成果。
