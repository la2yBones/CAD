# 待恢复任务持久化

GUI 批量处理需要在遇到 `needs_clarification` 时保存当前图纸现场并继续处理下一张。如果待恢复任务只保存在内存中，用户关闭 GUI 后就无法从恢复点继续，这与“批量处理可随时继续暂停项目”的目标冲突。

## Decision

1. GUI 批量处理中进入 `needs_clarification` 的单图纸任务应记录为待恢复任务。
2. 待恢复任务必须跨 GUI 重启持久化。
3. 待恢复任务至少保存输入文件、输出目录、处理参数、追问清单、澄清上下文、创建时间、更新时间和当前状态。
4. 批量队列遇到待恢复任务时不弹出追问窗口，而是继续处理下一张图纸。
5. 用户之后可以从待恢复任务列表选择某张图纸，补充答案后调用现有单图纸局部恢复流程继续建模。

## Consequences

- `CADProcessResult.to_dict()` 的摘要信息不足以作为恢复载体，需要单独的持久化记录。
- GUI 需要一个待恢复任务列表，区分 `failed`、`partial_completed` 和可继续的 `needs_clarification`。
- 批量处理的进度统计应把待恢复任务作为独立分类，而不是失败。
- 待恢复任务可能包含图纸结构和大模型中间结果，应存放在缓存/运行数据目录，不提交源码。
