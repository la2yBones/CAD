# 证据包驱动的大模型语义裁决

后续语义重建不再继续为具体图纸追加本地语义规则。螺母三视图、基板二视图等问题表明，本地规则一旦直接裁决“哪个视图是什么、哪个尺寸是什么角色、哪个局部图形是什么特征”，在复杂工程图上很容易形成误导性上下文；系统真正需要的是把可验证事实整理成证据包，由大模型完成图纸语义裁决，再由本地代码做合同校验和安全执行。

本 ADR 修正 ADR-0002：`SemanticPolicy` 不应长期作为“确定性语义裁决者”扩张，而应逐步收缩为证据整理、候选生成和安全校验边界。已经存在的确定性规则只允许保留在低层事实提取、几何归一化、候选证据组织和结果校验中；不得继续把具体图纸、具体零件或具体版式的解释规则堆进本地策略层。

## Considered Options

**A. 继续追加本地规则。**

短期能修单张图纸，例如把某个 16/20/40/60 绑定到特定语义，但这些规则依赖版式、零件类型和标注习惯，遇到更复杂或稍有变化的图纸就会误导大模型。拒绝。

**B. 把全量实体重新交给大模型自由理解。**

这会退回宽上下文调用：token 成本高，阶段职责混杂，容易截断，也会让第三阶段重新理解图纸而不是生成建模脚本。该方案与 ADR-0012 的阶段化载荷方向冲突。拒绝。

**C. 本地证据包 + 大模型语义裁决 + 本地合同校验。**

本地只提供可追溯证据：候选视图、候选尺寸、候选几何特征、空间关系、标注文本、bbox、来源图元、置信度和不确定项；大模型负责裁决视图角色、尺寸角色、特征角色、派生尺寸、缺失字段和追问需求；本地只验证裁决结果是否引用合法证据、派生公式是否可追溯、关键字段是否闭合、建模任务是否满足路径契约。选中。

## Decision

1. 引入“图纸证据包”作为第二阶段语义理解的主要输入形态。证据包使用稳定 ID 表达候选对象，例如 `V1`、`D1`、`G1`、`R1`；字段保留事实值和来源，不直接写死主视图、俯视图、凸台高度、板厚、螺纹长度等最终语义。
2. 大模型语义裁决负责把证据包解释为同一个三维零件：视图角色、尺寸角色、特征角色、派生尺寸、风险和追问清单都属于裁决结果，而不是本地规则的先验结论。
3. 本地校验器负责守边界：裁决结果只能引用证据包中存在的 ID、标注值和可验证派生公式；不得使用未裁决关键尺寸；不得把未闭合主体语义送入建模执行；不得让 FreeCAD 脚本绕过建模约束。
4. 第三阶段建模指令生成只消费已裁决的建模任务载荷，不接收全量原始实体，也不接收本地猜测出的具体操作序列。
5. 追问应来自语义裁决中的缺失主体语义或路径契约缺口，并尽量携带证据 ID、视图/标注定位和候选解释；GUI 不应把复杂语义问题退化成只能自由填写的一段文字。
6. 新增本地逻辑时，允许做解析、聚类、统计、候选生成、重复标注识别、尺寸文本解析和合同校验；禁止新增“某类图纸必然如何解释”的语义捷径，除非它是某条专用建模路径的显式路径契约。

## Consequences

- 语义质量的主要优化方向从“补本地规则”改为“提升证据包质量、裁决 schema、提示词和校验器”。
- 旧缓存不作为兼容目标；涉及语义载荷或裁决 schema 的改动后，通过清空缓存重新生成结果。
- `SemanticPolicy` 相关代码需要分阶段迁移：先保留兼容接口，再把硬语义绑定迁出为候选证据，最后将本地决策规则收缩到安全校验。
- 测试重点应从单张图纸的硬编码语义断言，转为证据包完整性、裁决引用合法性、派生尺寸可追溯性、追问触发边界和第三阶段载荷边界。
- 仍可保留专用建模路径，但专用路径的确定性规则必须表现为路径契约和执行约束，而不是隐藏在通用语义策略里的图纸解释规则。

## Migration Notes

1. 增加 `DrawingEvidencePackageBuilder`，把视图候选、尺寸候选、几何候选和空间关系统一成可引用证据。
2. 将 `SemanticPolicy.dimension_bindings` 中的硬角色逐步降级为候选标签和证据说明。
3. 增加 `LLMSemanticAdjudicator` 及其 JSON schema，输出裁决后的零件语义、尺寸计划、追问清单和建模任务前置条件。
4. 将追问生成改为消费裁决结果中的缺失项和证据 ID，而不是本地规则临时拼文案。
5. 由 `ModelingTaskBuilder` 从已裁决结果构造第三阶段建模任务载荷。
6. 新链路稳定后，删除为螺母三视图、基板二视图、螺栓二视图等案例临时加入的图纸特征解释规则。
