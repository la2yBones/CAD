# 候选尺寸不等同于建模许可

ADR-0013 已决定把本地语义规则收缩为证据整理、候选生成和安全校验。实现过程中仍存在一个容易混淆的边界：本地尺寸链、几何投影或版式关系可以产生“某个尺寸可能表示总长/高度/深度/螺纹长度”的候选，但这些候选不能直接进入建模指令，否则系统会把未裁决的推测包装成可靠尺寸，继续误导大模型和 FreeCAD 脚本。

典型风险包括：`9+39` 被猜成螺栓轮廓总长、`96` 被同时猜成长宽、`40` 被猜成凸台高度、`20/16` 被猜成板厚或凸出高度。它们都可能是有用证据，但只有经过语义裁决或用户确认后，才可以成为建模许可。

## Considered Options

**A. 本地候选直接进入 `allowed_dimensions`。**

实现最简单，但会延续旧问题：本地弱规则一旦猜错，下游会把猜测当成事实，用户也难以知道模型为什么这样建。拒绝。

**B. 删除所有本地候选生成。**

可以避免误导，但会浪费 CAD 解析已经得到的尺寸链、投影和重复标注证据，也会让大模型缺少可追溯候选。拒绝。

**C. 候选尺寸单独进入 `candidate_dimensions`，确认后才升级。**

本地继续生成候选，但候选只作为证据、风险和追问来源。只有语义裁决或用户澄清明确确认后，才升级为 `allowed_dimensions` 或可用的 `construction_dimensions`。选中。

## Decision

1. `dimension_plan` 必须区分 `allowed_dimensions`、`construction_dimensions`、`candidate_dimensions` 和 `unresolved_dimensions`。
2. `candidate_dimensions` 只表示“可能有用的证据”，不是最终建模许可，不得被建模指令生成阶段当作可直接使用尺寸。
3. 本地尺寸链、投影关系、相邻尺寸组合、重复标注和几何近邻推断只能产生 `binding_status="candidate"` 的候选绑定。
4. 用户在澄清界面确认候选后，该绑定才可升级为 `source="user_confirmed"`、`binding_status="adjudicated"`。
5. 用户选择“不确定 / 暂不使用这些候选”时，该候选必须从自动绑定中排除，不能在后续恢复中继续隐式使用。
6. 语义生成和建模指令提示词必须显式说明：`candidate_dimensions` 只能作为证据和风险，不是 key dimensions，也不是 FreeCAD 建模脚本的直接尺寸来源。
7. GUI 对候选确认问题应使用明确选项展示候选值和来源，并在提交前摘要说明哪些候选会被采用、哪些会被排除。
8. 待恢复任务应展示未决问题、候选选项、跳过细节和已有产物，避免用户恢复任务时无法理解挂起原因。
9. 尺寸绑定构建、尺寸权限计划和澄清答案应用必须分属不同模块：绑定构建器只负责生成绑定和候选，权限计划只负责分池和规则，澄清答案应用器只负责把用户结构化回答应用到绑定副本。
10. 语义裁决成功后，语义生成载荷不再携带原始尺寸列表、旧尺寸绑定或旧尺寸计划；第二阶段只能通过 `semantic_adjudication` 读取已裁决尺寸。旧 `dimension_plan` 只在语义裁决缺失或失败时作为兼容兜底。
11. 第二阶段 LLM 返回零件语义后，必须先经过零件语义后处理器，再进入 schema 校验和建模任务装配。后处理器可移除未授权 `key_dimensions`、规范化路径和中文化用户可见风险，但不得新增图纸语义或把候选尺寸升级为建模许可。
12. 第三阶段建模任务载荷的 `features` 节不得携带 `key_dimensions`。所有可用于 FreeCAD 建模的尺寸只能来自 `dimensions` 节；`recovery_hints.warnings` 和 `recovery_hints.uncertainties` 只解释风险，不提供建模许可。
13. 第三阶段 LLM 返回建模指令 JSON 后，必须经过建模指令后处理器再执行脚本。后处理器可移除未授权 `key_dimensions` 并中文化用户可见元数据，但不得修改脚本、补充新尺寸或把 warning/skipped detail 升级为建模事实。

## Consequences

- 建模质量不再依赖本地弱规则的暗中猜测；候选必须经过裁决或确认才能影响模型。
- 追问数量可能增加，但追问对象更清楚：它问的是“是否采用候选”，不是让用户凭空填写文字。
- 第三阶段建模任务载荷会更小、更干净，只包含已经裁决或确认的建模尺寸。
- 旧缓存不作为兼容目标；切换该策略后应清空旧分析缓存重新生成。
- 后续重构 `SemanticPolicy` 时，应优先把旧的硬绑定逻辑迁移到候选生成模块，而不是继续扩大本地语义裁决。
- `SemanticPolicy` 应保持为语义裁决编排器，不继续承载尺寸分类、权限分池、上下文裁剪或澄清答案变更等实现细节。
- `PartSemanticsValidator` 通过语义尺寸权限视图校验 key dimensions，不再自己解析语义裁决和兼容权限池。
- 未授权尺寸在第二阶段边界会被后处理器拦截并记录到 `uncertainties/warnings`，避免继续流入第三阶段建模任务。
- 建模指令生成阶段的提示词和载荷结构都不再提供 `features.key_dimensions` 旁路，减少模型从自然语言风险说明中重新抽取尺寸的机会。
- 建模执行阶段只把结构化、非推测性的 `skipped_features` 视为 `partial_completed`；推测性细节跳过会降级为中文 warning，不进入待恢复任务的缺失细节列表。
