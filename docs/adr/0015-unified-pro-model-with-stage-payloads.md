# ADR 0015: 统一 Pro 模型但保持阶段化载荷

## 状态

Accepted

## 背景

系统当前包含多个 DeepSeek 调用阶段：视图语义校正、图纸语义裁决、零件语义重建和建模指令生成。此前默认视图语义校正可使用 `deepseek-v4-flash`，其余阶段主要使用 `deepseek-v4-pro`。

复杂图纸处理中，阶段间模型风格差异可能带来理解偏差；同时，用户希望减少跨模型切换对上下文缓存和判断一致性的影响。

## 决策

默认所有 DeepSeek 阶段统一使用 `deepseek-v4-pro`。

系统不采用同一个长对话上下文连续推进所有阶段。各阶段仍保持独立 JSON 请求，跨阶段连续性由本地结构化产物承接，包括视图判定载荷、图纸证据包、语义裁决结果、零件语义、建模路径裁决、建模任务载荷、澄清上下文和恢复提示。

DeepSeek 上下文缓存只作为性能优化，不作为系统正确性的基础。

## 后果

- 视图语义校正、语义裁决、语义重建和建模指令生成默认使用相同模型，减少阶段间模型风格差异。
- 不依赖模型会话记忆，仍可对每个阶段做 schema 校验、尺寸权限校验、建模任务完整性诊断和脚本可执行性校验。
- 局部恢复继续基于 `clarification_context` 和结构化恢复提示，不需要重放完整长对话。
- 配置仍保留按阶段覆盖模型的能力，便于后续性能调优或降级，但默认策略是统一 `deepseek-v4-pro`。
