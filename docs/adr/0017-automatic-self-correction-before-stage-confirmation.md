# ADR 0017: 自动自纠优先于阶段确认

## 状态

Accepted

## 背景

当前阶段确认对话框在 LLM 阶段完成后立即弹出，要求用户手动选择"继续/停止/重跑/自纠"。实际使用中存在两个问题：

1. 用户把应用放在后台时，模态对话框被遮挡导致处理卡住。
2. 自纠和重跑是用户手动触发的，但系统已有足够信息自动判断是否需要自纠——校验器产出的结构化问题可以直接驱动自纠，不需要用户做这个决策。

ADR 0016 确立了最小人工介入原则：用户主要承担进度监督和错误发现的角色，而不是常规语义补全者。当前实现中"是否自纠"仍由用户手动选择，与该原则不一致。

## 决策

### 自动自纠优先

阶段完成后，系统先执行自动质量检测。校验失败时自动触发模型自纠，最多 2 轮。自纠完成后才进入阶段确认。

```
阶段完成 → 自动校验 → (如需)自动自纠第1轮 → 校验 → (如需)自动自纠第2轮 → 阶段确认对话框
```

### 阶段确认对话框简化

阶段确认对话框只保留三个动作：

- **继续**：接受当前阶段结果。主体安全边界未闭合时不可用。
- **停止**：终止当前图纸处理。
- **重跑**：弹出勾选界面，用户选择保留的部分成果后带约束重跑。

移除"更多信息"菜单中的"重跑当前阶段"和"让模型自纠"选项。自纠由系统自动执行，重跑通过独立的勾选界面触发。

### 带部分成果重跑

用户选择重跑时，弹出勾选界面展示当前阶段的部分成果。勾选粒度为特征级：

- 视图语义校正阶段：视图角色
- 零件语义生成阶段：主体特征、增材特征、减材特征、关键尺寸
- 建模指令生成阶段：已完成特征、跳过特征

勾选项作为约束传入 LLM 的 `previous_output`，模型必须遵守已确认结果，只重新生成未勾选的部分。

### 阶段确认呈现状态

| 自纠后状态 | 继续按钮 | 对话框标题 |
|---|---|---|
| 校验通过（无自纠或自纠成功） | 可用 | 阶段完成 |
| 自纠部分解决，仍存风险 | 可用 | 阶段完成（自纠已执行） |
| 自纠未解决，主体安全边界未闭合 | 不可用 | 阶段完成（自纠未完全解决） |

### 实施分期

**第一期**：改造阶段确认对话框 + 零件语义生成自动自纠

- 零件语义阶段的校验器最完善，改造收益最大
- 对话框重写是所有阶段共享的基础设施

**第二期**：视图语义校正 + 语义裁决 + 建模指令生成的自动自纠

- 这三个阶段相对稳定，后续迭代

## 后果

- 用户不再需要判断"是否自纠"，系统自动处理合同类错误。
- 阶段确认对话框更简洁，聚焦于监督和终止决策。
- 重跑通过勾选界面实现，用户可以精确控制保留哪些成果。
- 自纠过程必须有用户可见状态，不能作为后台静默重试。
- 阶段报告需要记录自纠触发原因、轮次、校验问题、修正目标和结果。
- 逐阶段确认默认关闭，用户主动开启后才弹出确认对话框。
