# 领域文档

本文件说明工程技能在理解仓库时应如何读取领域文档。

## 开始探索前先读取

- 根目录的 `CONTEXT.md`
- 与当前工作相关的 `docs/adr/` 中的 ADR

本仓库采用单上下文布局，因此默认只有一份全局 `CONTEXT.md`。
如果未来出现 `CONTEXT-MAP.md`，则应按映射读取对应上下文文档。

如果这些文件不存在，继续工作即可；不要因为缺少它们就中断流程。

## 当前布局

```text
/
├── CONTEXT.md
├── docs/adr/
└── src/
```

## 使用项目自己的术语

当输出内容涉及领域概念时，优先使用 `CONTEXT.md` 中已经定义的词汇；不要随意换成近义词，避免项目语言漂移。

如果需要表达的概念还不在词汇表里，先判断它是否真的是一个新的领域概念；若是，再考虑后续补充文档。

## 发现 ADR 冲突时

如果你的建议与已有 ADR 冲突，应明确指出冲突，而不是静默覆盖已有决策。

示例：

> 这与 ADR-0007 的既有决策冲突，但值得重新讨论，因为……
